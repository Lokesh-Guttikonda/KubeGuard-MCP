## ✨ Why KubeGuard

| The 3 a.m. problem | What KubeGuard does |
|---|---|
| Pod JSON, events, logs and YAML are scattered; the root cause hides in the *combination* | One-shot **correlator** cross-references every signal and scores the evidence |
| "Just bump the memory" / "just restart it" guesses | **Deterministic** root cause + the **exact unified diff** for *your* file — comments and formatting preserved |
| Logs contain DB passwords, AWS keys, JWTs, kubeconfig tokens | A **redaction firewall** masks them *before* analysis and on *every* output path |
| AI agents happily run `kubectl delete ns` | A **zero-trust policy engine** classifies every command `SAFE_READ` / `APPROVAL_REQUIRED` / `BLOCKED_DESTRUCTIVE` |
| LLM triage costs money and ships your data out | Fully offline. LLMs are an *optional second opinion* on redacted data only |
| Tooling that works in one terminal only | Pure stdlib, Python 3.9 – 3.14, Linux / macOS / **Windows (incl. cp1252 consoles)** |

## 🚀 60-second quick start

No `pip install`, no virtualenv, no API key:

```bash
git clone https://github.com/Lokesh-Guttikonda/KubeGuard-MCP.git
```

```bash
cd KubeGuard-MCP
```

```bash
python scripts/demo_offline.py
```

On Windows, enable full Unicode glyphs first (without it the output cleanly degrades to ASCII):

```bash
set PYTHONUTF8=1
```

Install the `kubeguard` command (still zero runtime dependencies):

```bash
pip install .
```

```bash
kubeguard diagnose examples/crashloop_secret_leak
```

Or run it straight from GitHub with [uv](https://docs.astral.sh/uv/):

```bash
uvx --from git+https://github.com/Lokesh-Guttikonda/KubeGuard-MCP kubeguard demo
```

1. **Ingress firewall** — `redactor.py` masks secrets in logs/events before any detector reads them.
2. **Correlate** — `correlator.py` normalises Pod status, Events (`v1` and `events.k8s.io/v1`), logs, Deployments,
   Services, Secrets/ConfigMaps inventories, Nodes, Endpoints, `docker inspect` and docker-compose, then runs six
   detectors that each produce weighted evidence and a confidence score.
3. **Patch** — `patcher.py` turns path-addressed edits into surgical line edits using the spans recorded by
   `yaml_lite.py`, so the diff touches only what must change (comments, key order and quoting survive).
4. **Classify** — every suggested command (and every action an agent proposes) goes through `policy.py`.
5. **Egress firewall** — reports, diffs, MCP responses and LLM prompts are redacted again on the way out.

## 🔬 What gets diagnosed — and fixed

| Failure | Signals correlated | Sub-causes | Deterministic fix |
|---|---|---|---|
| **OOMKilled** | `lastState.terminated.reason`, exit 137, node `OOMKilling` events, OOM log lines, JVM `-Xmx` / Node `--max-old-space-size` (env, args, Dockerfile, logs) vs. the limit, `docker inspect` `State.OOMKilled` | `heap_exceeds_limit`, `limit_too_low` | raise `limits.memory` (Guaranteed-QoS aware) or add limits; `-Xmx` → `-XX:MaxRAMPercentage=75.0` in the manifest or **Dockerfile**; docker-compose `mem_limit` |
| **CrashLoopBackOff** | waiting reason, `BackOff` events, restart count, exit-code semantics, logs | `db_auth_failure`, `missing_config`, `liveness_probe`, `exec_format`, `command_not_found`, `permission_denied`, `application_error`, `oom` (symptom) | plaintext env → `secretKeyRef` matched to (rotated) Secret keys; inject missing env from a Secret/ConfigMap; fix probe port or `initialDelaySeconds` from the measured startup time |
| **ImagePullBackOff** / `ErrImagePull` | waiting reason, pull events, `dockerconfigjson` Secrets (registry hosts decoded) | `registry_auth`, `tag_not_found`, `invalid_name`, `rate_limited`, `registry_unreachable` | attach the pull secret for that registry; roll back to the last known-good tag; lowercase the repository |
| **CreateContainerConfigError** | waiting message, events, Secret/ConfigMap inventories | `missing_key`, `missing_secret`, `missing_configmap`, `run_as_non_root` | fix key/object-name typos (env, envFrom, volumes); `runAsUser: 10001` + `USER` in the Dockerfile |
| **Unschedulable** | `PodScheduled=False`, `FailedScheduling` breakdown, node allocatable & labels | `insufficient_resources`, `node_selector_mismatch`, `untolerated_taint`, `unbound_pvc`, `too_many_pods` | right-size requests to fit the largest node; fix `nodeSelector` value/key typos |
| **ServicePortMismatch** | Service selector/`targetPort` vs. template labels & `containerPort`s, "listening on" log lines, Endpoints, pod readiness | `target_port`, `selector_mismatch` | point `targetPort` at the named container port; align the selector |

Root causes outrank symptoms (a crash loop caused by OOM is reported as a symptom of `OOMKilled`), results are
fully deterministic (same bundle → same incident ID, report and patch), and no wall-clock time appears in output.

## 🔥 Secret & PII firewall

Precompiled rules with substring pre-filters, a case-folded fast path and a single splice pass (~6 MB/s of
realistic logs on one core). Rules run in priority order and a generic rule can never overlap a span claimed by a
specific one, so `postgres://app:hunter2@db` becomes `postgres://app:[REDACTED:db_connection_string]@db` — the
host and user stay visible for debugging. Redaction is idempotent and every finding is audited by rule, category,
severity, line and column — never by value.

| Rule | Category | Severity | Detects |
|---|---|---|---|
| `private_key` | secret | critical | PEM / OpenSSH / PGP private key blocks |
| `aws_access_key_id` · `aws_secret_access_key` · `aws_session_token` | secret | critical | AWS credentials (env, JSON, CLI output) |
| `kubeconfig_token` | secret | critical | kubeconfig `token`, `id-token`, `client-key-data` … |
| `jwt` · `bearer_token` · `basic_auth` | secret | high | JWTs (incl. service-account tokens), `Authorization` headers |
| `db_connection_string` · `url_credentials` · `url_param_secret` | secret | critical / high | passwords in Postgres/MySQL/Mongo/Redis/AMQP/… URLs, `user:pass@host`, JDBC `password=` |
| `github_token` · `gitlab_token` · `slack_token` · `stripe_key` · `google_api_key` · `llm_api_key` | secret | high / critical | provider API keys (incl. Anthropic, OpenAI, Groq) |
| `docker_auth` | secret | critical | registry `auth` inside docker `config.json` |
| `k8s_env_secret` | secret | critical | `- name: DB_PASSWORD` / `value: …` (YAML, JSON — even across diff hunks) |
| `k8s_secret_data` | secret | critical | every value under `data`/`stringData` of `kind: Secret` (structural pass, YAML & JSON) |
| `json_secret_field` · `secret_assignment` | secret | high | `"client_secret": "…"`, `.env` `KEY=value`, `password: …` |
| `credit_card` (Luhn) · `us_ssn` · `email` | pii | high / medium | personal data (`--no-pii` to keep) |
| `ipv4` | pii | low | opt-in (`--ips`) — pod IPs are usually useful for triage |

False positives are actively suppressed: `secretName:`, `DB_PASSWORD_FILE=`, `max_tokens=1024`,
`InvalidPasswordError: password authentication failed`, `dsn=settings.database_url`, `${VAR}` placeholders,
`git@github.com:` and in-cluster `*.svc.cluster.local` addresses are left alone.

## 🚦 Zero-trust policy engine

| Verdict | Meaning | Examples |
|---|---|---|
| 🟢 `SAFE_READ` | read-only and non-sensitive; may run unattended | `kubectl get/describe/logs/top/events`, `rollout status`, `auth can-i`, `docker ps/logs/inspect`, `helm status/get/template` |
| 🟡 `APPROVAL_REQUIRED` | mutates state, opens a shell/tunnel, or reads secret values | `kubectl apply/patch/scale/rollout restart/exec/port-forward`, `delete pod <name>`, `get secret -o yaml`, `config view --raw`, `docker run`, `helm upgrade` |
| 🔴 `BLOCKED_DESTRUCTIVE` | irreversible, bulk, privilege-escalating or injected | `delete ns/node/pv/pvc/crd`, `delete --all`/`-l`/`-f`, `--force --grace-period=0`, `drain`, `NoExecute` taints, `replace --force`, `apply --prune`, cluster-admin bindings, impersonating `system:masters`, node debugging, mutations in `kube-system`, `docker system/volume prune`, `--privileged`, `--pid=host`, docker.sock mounts, `helm uninstall`, **any** `;` `&&` `\|` `>` `$(…)` or non-allowlisted binary |

Roles (`--role` / `KUBEGUARD_ROLE`): `viewer` may only run `SAFE_READ`; `operator` may run `APPROVAL_REQUIRED`
once a human approved it; `admin` may additionally break glass on `BLOCKED_DESTRUCTIVE` — only with approval **and**
a written justification, which is flagged in the audit trail. `analyze_rbac()` statically flags wildcard grants,
Secret readers, `pods/exec`, `escalate`/`bind`/`impersonate`, token minting, webhook control, cluster-admin and
public-group bindings.

every CLI command and exit code, and **Windows UTF-8 safety** (subprocesses under `cp1252` and `ascii` code pages,
isolated `python -I` runs proving zero dependencies, CRLF manifests, byte-exact MCP UTF-8 under any locale).
CI runs them on Linux, macOS and Windows for Python 3.9 – 3.14, plus `ruff`, a zero-dependency demo job, a wheel
build + install smoke test and the README freshness check.

## 🔒 Security model

- **No credentials, no execution.** KubeGuard analyses data you give it; it never talks to a cluster, a registry or
  the internet (except the opt-in LLM reviewer).
- **Two firewalls.** Secrets are masked on ingress (before detectors run) and again on egress (every report, diff,
  MCP result and LLM prompt).
- **Read-only MCP surface.** Tools cannot mutate anything; `bundle_path` is confined to `KUBEGUARD_MCP_ROOTS`
  (default: the server's working directory); stdout carries only JSON-RPC, diagnostics go to stderr.
- **Default deny.** Unknown binaries are blocked, unknown verbs need approval, shell metacharacters are rejected.
- **Patches stay local.** `--write-fixed` writes the patched files to a directory you choose; displayed diffs are
  always redacted (the CLI warns if a hunk contained a masked value).
